# MERCHROOM — คู่มืออ่าน Database และ Architecture สำหรับทุกคน

เอกสารนี้อธิบายรูปที่แนบไว้ด้วยภาษาทั่วไป ไม่จำเป็นต้องเขียนโค้ดเป็นก็อ่านได้

## 1. ระบบแบ่งเป็น 3 ฝั่ง

1. **หน้าร้าน (Frontend)** คือเว็บไซต์ที่ลูกค้าและแอดมินเปิดใช้ผ่าน browser
2. **หลังร้าน (Backend)** คือผู้ตรวจสอบสิทธิ์ คำนวณยอด สร้างออเดอร์ ลดสต็อก และคุยกับบริการภายนอก
3. **คลังข้อมูล (MongoDB)** คือที่เก็บข้อมูลถาวรของสินค้า ผู้ใช้ ตะกร้า ออเดอร์ และการชำระเงิน

พูดง่าย ๆ: Frontend เป็นหน้าร้าน, Backend เป็นพนักงานและกติกาของร้าน, Database เป็นสมุดบัญชีและคลังสินค้า

## 2. อ่าน ER Diagram อย่างไร

- กล่องหนึ่งกล่องคือข้อมูลหนึ่งประเภท เช่น Product คือสินค้า, Order คือคำสั่งซื้อ
- `PK` คือรหัสเฉพาะของข้อมูลหนึ่งแถว/รายการ
- `FK` คือรหัสที่ใช้เชื่อมไปยังอีกกล่องหนึ่ง
- `1 : N` แปลว่า หนึ่งรายการเชื่อมกับได้หลายรายการ เช่น ศิลปิน 1 คนมีสินค้าได้หลายชิ้น
- `items[]` แปลว่า ข้อมูลย่อยหลายรายการถูกเก็บรวมอยู่ใน Order หรือ Cart เดียวกัน

## 3. ความสัมพันธ์สำคัญ

| สิ่งที่เกี่ยวกัน | ความหมายในร้าน |
|---|---|
| Artist -> Product | ศิลปิน/แบรนด์หนึ่งรายมีสินค้าได้หลายชิ้น |
| Category -> Product | หมวดหนึ่งหมวดมีสินค้าได้หลายชิ้น |
| User -> Cart | ลูกค้ามีตะกร้าสำหรับเก็บสินค้าที่กำลังสนใจ |
| Cart -> Product | ตะกร้าระบุว่าสินค้าชิ้นใด จำนวนเท่าไร |
| User -> Order | ลูกค้าคนหนึ่งสั่งซื้อได้หลายครั้ง |
| Order -> Payment | การสั่งซื้อมีการบันทึกการชำระเงินแยก เพื่อเช็กได้ว่าจ่ายสำเร็จหรือไม่ |
| User + Product -> Review | ลูกค้าเขียนคะแนนและความคิดเห็นต่อสินค้าได้ |
| ProductChangeLog -> Product/User | เก็บว่าใครแก้สินค้าอะไรและแก้จากค่าเดิมเป็นค่าใด |

## 4. สิ่งที่ seed.js ใส่ไว้ให้เริ่มทดสอบ

`server/seed.js` ล้างข้อมูลชุดเดิม แล้วสร้างข้อมูลเริ่มต้นใหม่ตามนี้

- ผู้ใช้ 15 บัญชี: ลูกค้า 9 และแอดมิน 6
- หมวดสินค้า 5 หมวด
- ศิลปิน/แบรนด์ 14 ราย
- สินค้า 32 ชิ้น พร้อมราคา จำนวนคงเหลือ tag ไซส์ และความเชื่อมโยงกับ artist/category
- ออเดอร์ตัวอย่าง 3 รายการ

ไฟล์นี้ล้าง Cart, Payment และ Review แต่ยังไม่ได้สร้างข้อมูลตัวอย่างใหม่ให้สาม collection นี้ ดังนั้นถ้าเห็นตารางว่างหลัง seed ถือเป็นพฤติกรรมตามโค้ดปัจจุบัน

## 5. ข้อสังเกตที่ควรรู้ก่อนพัฒนาต่อ

- ข้อมูล mock ใน `seed.js` บางช่อง เช่น `memberSince`, `orderNumber`, `trackingNumber` และ `paymentStatus` ยังไม่มี field รองรับใน User/Order schema จึงไม่ได้ถูกบันทึกจริงโดย Mongoose
- PromoCode มีอยู่ในฐานข้อมูล แต่ยังไม่มีการอ้างถึงจาก Cart หรือ Order จึงยังตามไม่ได้ว่าออเดอร์ใดใช้ส่วนลดใด
- Cart มี `variant_id` แต่ Product ยังไม่ได้มี ProductVariant schema สำหรับเก็บสต็อกแยกตามสี/ไซส์

สามข้อข้างต้นไม่ใช่ข้อผิดพลาดของรูป แต่เป็นช่องว่างที่รูป ER ทำให้ทีมเห็นตรงกันก่อนจะเพิ่มฟีเจอร์ต่อ
